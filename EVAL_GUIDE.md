# GenMedia SxS — Image & TTS Evaluation Guide

How to add inputs and run a side-by-side (SxS) evaluation for the two new modalities:

- **Image SxS** — Gemini image models vs GPT-image (FAL), text-to-image (T2I) and image-edit (I2I)
- **TTS SxS** — Gemini 3.1 Flash TTS vs ElevenLabs

Both follow the same loop: **upload a cases JSON → models generate in parallel → an AI judge scores each pair → you (and others) vote blind A/B → see the leaderboard.**

> **Live app:** https://genmedia-sxs-v2-440790012685.us-central1.run.app
> Access is Google-IAM gated (sign in with your @google.com account). Admin actions (upload/run/delete) require the admin login in the top-right **Admin** page.

---

## 1. Image SxS

Open **Image SxS** in the nav (`/image-sxs`).

### 1a. Write your cases JSON

```json
{
  "cases": [
    {
      "id": "img1",
      "mode": "t2i",
      "prompt": "A single red maple leaf on a clean white background, studio product photo",
      "matchup": "gemini-3.1-flash-image_vs_gpt2-medium"
    },
    {
      "id": "img3",
      "mode": "i2i",
      "prompt": "Make it snow heavily and add a warm sunset glow",
      "input_image": "refs/koi.png",
      "matchup": "gemini-3-pro-image_vs_gpt2-high"
    }
  ]
}
```

**Fields**

| field | required | values |
|---|---|---|
| `id` | yes | unique short id for the case |
| `mode` | yes | `t2i` (text-to-image) or `i2i` (image edit) |
| `prompt` | yes | the generation / edit instruction |
| `input_image` | i2i only | relative path to a reference image you upload alongside the JSON (e.g. `refs/koi.png`) |
| `matchup` | optional | which pair to compare (defaults to matchup #1) |

**Matchups** (Gemini side vs GPT-image quality tier):

| matchup id | left (Gemini) | right (GPT-image) |
|---|---|---|
| `gemini-3.1-flash-image_vs_gpt2-medium` | gemini-3.1-flash-image | gpt-image-1 **medium** |
| `gemini-3-pro-image_vs_gpt2-high` | gemini-3-pro-image | gpt-image-1 **high** |
| `instant-ramen_vs_gpt2-low` | instant-ramen | gpt-image-1 **low** |

> ⚠️ `instant-ramen` is an EAP model and currently returns 404 on this project. That side will show as an error (the batch still completes); switch to one of the first two matchups for working comparisons until the model is enabled.

A ready sample lives at `backend/image_cases.sample.json`.

### 1b. Run it

- **In the UI:** Image SxS → *Compose & Run* tab → drop your `cases.json` (and any reference images for I2I) → **Run**.
- **Or via API:**
  ```bash
  TOKEN=$(python3 -c "import hashlib;print(hashlib.sha256('project-pulse-sxs:v1:admin:<ADMIN_PASS>'.encode()).hexdigest())")
  curl -X POST "$URL/api/image/upload" -H "X-Admin-Token: $TOKEN" \
    -F "cases=@image_cases.sample.json;type=application/json"
  # I2I: also add  -F "files=@refs/koi.png"
  ```

Each case becomes a job: both models generate in parallel, then a Gemini judge scores **prompt-following, aesthetic, detail, artifact-free** (plus **edit-fidelity** for I2I) and picks a winner.

### 1c. Evaluate

- **Blind voting:** *Blind Eval* tab shows image **A** vs **B** with no model names. Rate each metric and submit — your vote records the real winner behind the scenes.
- **Results:** *Results* tab shows per-matchup win-rates and per-metric breakdowns (human votes + AI judge).

## 2. TTS SxS

Open **TTS** in the nav (`/tts-sxs`). Every case is generated by **Gemini 3.1 Flash TTS** and **ElevenLabs** and compared blind.

### 2a. Write your cases JSON

```json
{
  "cases": [
    {
      "id": "t1",
      "text": "[cheerful] Have a wonderful day! Everything feels possible.",
      "voice": "Kore",
      "style_prompt": "Warm, upbeat morning-radio host.",
      "language": "en"
    },
    {
      "id": "t3",
      "mode": "multi",
      "text": "Joe: How's the launch going?\nJane: [excited] Better than we imagined!",
      "speakers": [
        { "speaker": "Joe", "voice": "Kore" },
        { "speaker": "Jane", "voice": "Puck" }
      ],
      "style_prompt": "Casual chat between two startup co-founders."
    }
  ]
}
```

**Fields**

| field | required | values |
|---|---|---|
| `id` | yes | unique short id |
| `text` | yes | the transcript to speak. May include inline **audio tags** like `[whispers]`, `[shouting]`, `[laughs]`, `[excited]`, `[sighs]` |
| `voice` | single-speaker | one of the 30 Gemini voices (Kore, Puck, Zephyr, Charon, …) — see `GET /api/tts/voices` |
| `style_prompt` | optional | director's notes: tone, accent, pace, vibe (e.g. "tense thriller narrator, hushed") |
| `language` | optional | BCP-47 hint (e.g. `en`); auto-detected if omitted |
| `mode` | multi-speaker | set to `"multi"` for a 2-speaker conversation |
| `speakers` | multi only | up to 2 `{ "speaker": "<name used in text>", "voice": "<voice>" }` |

> The transcript and the directions should agree ("who/what/how" aligned). ElevenLabs uses the same text + voice; Gemini-only `[tags]` are stripped for the ElevenLabs side automatically.

A ready sample lives at `backend/tts_cases.sample.json`.

### 2b. Run it

- **In the UI:** TTS → *Compose & Run* tab → either use the compose form (voice dropdown, style notes, audio-tag buttons, multi-speaker toggle) for a quick one-off, or drop a `cases.json` → **Run**.
- **Or via API:**
  ```bash
  curl -X POST "$URL/api/tts/upload" -H "X-Admin-Token: $TOKEN" \
    -F "cases=@tts_cases.sample.json;type=application/json"
  ```

Each case → both engines synthesize audio → a Gemini audio judge scores **naturalness, style-adherence, expressiveness, pacing, pronunciation** and picks a winner.

### 2c. Evaluate

- **Blind voting:** *Blind Eval* tab plays clip **A** vs **B** (no engine names). Rate and submit.
- **Results:** *Results* tab shows Gemini-vs-ElevenLabs win-rates and per-metric breakdowns.

## 3. Standard intake APIs

The upload endpoints above are the UI's path. For a scripted or customer-facing
integration there is a documented contract that also lets you **name the models
to run**, and that accepts **media the customer already generated**:

```
POST /api/{sxs,image,tts}/prompts    # prompts + model names  -> we generate
POST /api/{sxs,image,tts}/outputs    # prompts + media URLs   -> we register
```

Either way the case lands in the same blind arena, judge, and analytics. See
**[`docs/api/DATA_INTAKE.md`](docs/api/DATA_INTAKE.md)** for the full contract:
per-modality case schemas, the `outputs` manifest, model discovery
(`GET /api/intake/models`), the `run_eval` flag, and the partial-success
response envelope.

## 4. Notes

- **Isolation:** Image and TTS use their own Firestore collections (`image_jobs`/`image_votes`, `tts_jobs`/`tts_votes`) and GCS prefixes (`images/`, `audio/`). The existing **video** SxS app is untouched.
- **Re-run a failed side:** use the *Retry* action on a job, or `POST /api/{image,tts}/jobs/{job_id}/retry`.
- **Keys:** `ELEVENLABS_API_KEY` is provided via Secret Manager; Gemini/FAL use the runtime service account + `FAL_KEY` secret. Nothing sensitive is committed.
- **Local dev:** `cd backend && ADMIN_PASS=password python3 -m uvicorn main:app --port 8077` then `cd frontend && npm run dev`.

Tech:4 Dep:3 Com:5
Your Answer
I'd start with the ingestion pipeline -- chunking documents into 512 token segments with overlap. For embeddings, I'd use E5-large or BGE, deployed via ONNX for speed. Vector store: Pinecone or pgvector depending on scale. Hybrid retrieval combining dense vectors with BM25, then rerank with a cross-encoder...
Correct
  • Good chunking strategy with overlap
  • Hybrid retrieval (dense + sparse)
  • Mentioned cross-encoder reranking
  • Clear, structured communication
Missed
  • No document preprocessing (OCR, tables)
  • No eval metrics (MRR, NDCG, recall@k)
  • Missing: document updates & index freshness
Tip
When discussing RAG at scale, always address the data pipeline (ingestion, updates, freshness) and evaluation strategy. Interviewers want end-to-end thinking.
Model Answer
Strong answer covers: (1) Preprocessing -- OCR, table extraction, metadata. (2) Chunking -- semantic/recursive, not fixed-size. (3) Embedding -- MTEB benchmark selection, domain fine-tuning. (4) Indexing -- HNSW params, sharding for 10M. (5) Retrieval -- hybrid, query expansion, HyDE. (6) Reranking -- cross-encoder + latency budget. (7) Eval -- offline (NDCG, MRR) + online (CTR). (8) Freshness -- incremental indexing, TTL.
